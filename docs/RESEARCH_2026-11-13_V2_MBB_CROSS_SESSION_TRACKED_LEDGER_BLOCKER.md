## Newly established source-level cause

The production `multi_broker_bridge/auto_paper.py` uses a persistent SQLite `tracked` table with **`symbol` as the primary key**, populated when a BUY is **accepted** (not necessarily filled). The scan loads *all* rows in `tracked` without filtering by trading session; a fresh BUY_WATCH on a tracked symbol is rejected as `PRIOR_ENTRY_NOT_ELIGIBLE_FOR_DISCOUNTED_REENTRY` unless the exceptional broker-verified >=2% profitable, >=0.25% discounted, pre-10:00 CT reentry conditions are all satisfied. This exceptional path searches SELL attempts for only the current and previous New York dates, and does not grant an ordinary fresh entry on later sessions.

The only `DELETE FROM tracked` in the production Python package is in `auto_paper.py` for a terminal **canceled/expired/rejected entry order with zero filled quantity**. The `paper_time_exit.py` mandatory-flatten handler expressly leaves the tracking ledger in place pending fill reconciliation. No verified-filled-SELL-to-archive/clear lifecycle was found in that production path. **This identifies a specific persistent-state cause for repeat-day BUY_WATCH suppression, not merely a strict extension cap.** Do not delete entries on a flat broker snapshot alone: canceled/unknown/partial orders require broker fill reconciliation.

## Implication and release boundary

The prior-entry ledger is deliberately safety-conservative, but it **does not distinguish a fully exited prior session from an active/unknown-order exposure**. Unless separately reconciled, once the universe is traded it can remain blocked on later dates. This is a *coverage/availability defect*, **not** evidence that allowing additional buys would be profitable; missing issuer-specific news clearance and existing quote, extension and broker-only risk gates remain independent blockers.

For a **separately authorized PAPER-only release**, evaluate an account- and entry-order-ID-scoped archival transition only when the correct Alpaca PAPER broker verifies the final SELL fill(s), exact closed quantity, terminal status, no own pending orders and no residual same-account position. Retain same-session anti-churn/idempotency; permit a new-session evaluation only after a fresh signal and all current prebuy protections, including `NEWS_CLEAR_ASOF`. Missing/partial/unknown broker evidence remains **blocked**. No historical ledger should be manually cleared, and no V1 safety guard, stop, holiday gate, 13:40 flatten or LIVE authority should be changed by this research.
